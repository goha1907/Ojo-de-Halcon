# Ojo de Halcón

Публичный сервис, где человек отслеживает **все свои государственные трамите в одном месте**
(путь к гражданству и DNI в Аргентине) и получает уведомления в Telegram, не заходя по очереди
на пять разных сайтов.

> «Соколиный глаз»: сервис, который всё видит за тебя. Репозиторий: `goha1907/Ojo-de-Halcon`.
>
> Статус: идея / проектирование. Кода пока нет. Прототип для личного использования —
> `../Parser_juzgado` (парсеры, этапы, интерфейс); из него переносится логика, а не код «как есть».

## Зачем

Сейчас, чтобы понять, где твоё дело, нужно вручную ходить на разные госсайты, у части из которых
нет нормальной формы (RENAPER), а часть периодически падает (Migraciones). Информация разрознена,
термины «заумные», статус «изменился» никто не присылает.

Цель: **один кабинет, один Telegram**, понятные статусы по-русски, подсказки «что это значит и
что делать дальше».

## Для кого

Люди, оформляющие гражданство Аргентины и связанные с ним документы (в первую очередь
русскоязычные). Интерфейс: RU в первую очередь, ES — вторым; закладывать i18n сразу.

## Как это выглядит для пользователя

1. **Регистрация / профиль**: имя, фамилия, дата рождения.
2. **Настройки → Telegram**: сервис генерирует уникальный одноразовый код, пользователь отправляет
   его боту — аккаунт привязан, уведомления идут в его Telegram.
3. **Выбор событий**: о чём уведомлять (смена статуса, одобрено, напечатано, передано на почту,
   доставлено, новое движение по делу, превышен обычный срок и т.п.).
4. **Трекеры** (каждый — своя вкладка):

| Трекер | Что отслеживаем | Источник | Вход |
|--------|-----------------|----------|------|
| Одобрение DNI в Migraciones | статус «precaria / consulta unificada» | migraciones.gob.ar/accesible/consultaTramitePrecaria/ConsultaUnificada.php | номер трамите (+ данные профиля) |
| Изготовление DNI в RENAPER | состояние трамите, этапы | mitramite.renaper.gob.ar | номер трамите |
| DNI на почте | движение отправления | correoargentino.com.ar/formularios/ondng | номер трамите |
| Трамите на гражданство | статус в Migraciones | migraciones.gob.ar/accesible/consultaTramiteCiudadania/ConsultaCiudadania.php | номер трамите + дата рождения |
| Гражданство в суде | ход дела, этапы, сроки | scw.pjn.gov.ar | номер дела / год |

5. **Полезные ссылки** (справочная вкладка): справка о датах въезда/выезда (Migraciones),
   турно на справку о несудимости в Аргентине, оформление гражданства онлайн, загрузка документов
   в трамите гражданства (RADEX) и т.д.
6. **Новости проекта**: блог — какие сервисы подключили, что изменилось, плановые работы.

## Правила доступа и подписки (решения)

1. **Одно дело в каждом разделе.** Пользователь регистрируется под своими именем, фамилией и датой
   рождения и может отслеживать только **своё** дело. Бэкенд сверяет данные дела с профилем и не
   даёт подписаться на чужое.
2. **Платная подписка на месяц включает по одному делу в каждом из разделов.** Оплата: песо, крипта
   (стейблкоины), возможно доллары.
3. **Новое дело — после завершения предыдущего** в том же разделе (например, новое DNI после
   получения гражданства). «Критичные» случаи (опечатка в номере, аннулированное трамите, потерянный
   DNI и новый номер, дело передано в другой суд) описываем отдельно.

### Принятые решения (после обсуждения)

- **Регистрация и вход**: e-mail + пароль, подтверждение почты (реализовано, выключено флагом
  `EMAIL_VERIFICATION_REQUIRED` до подключения почтового сервиса). **Telegram только для
  уведомлений**: подключается в настройках одноразовым кодом, для входа не используется.
- **Онбординг после регистрации** (необязательный): имя, фамилия, дата рождения и что человек
  отслеживает; по профилю позже будем сами искать дела там, где это возможно.
- **Уведомления** включаются по сервисам (5 штук), по умолчанию все включены.
- **Удаление аккаунта** в настройках: полное удаление данных с подтверждением паролем.
- **Пробный период**: 1 любое дело на неделю (на этапе разработки не критично, но закладываем).
- **Несколько дел** (например, для ребёнка): разрешаем, но нужно чётко определить, как это
  считается в оплате и как не дать добавлять чужие трамите. Детали — при разработке.
- **Роль адвоката** (позже): человек регистрирует своего адвоката, и уведомления по одному делу
  получают оба. Это «одно дело, два получателя» — в модели данных заложить связь «дело ↔ несколько
  получателей» с ролями (владелец / представитель), не размножая слоты подписки.

## Монетизация

Подписка на месяц (ориентир 5000 ARS), в состав входит по одному отслеживаемому делу в каждом
разделе. Пробный период: 1 дело на неделю.

Платежи по этапам:
1. **Разработка и тесты**: заглушка (`billing` с фейковым провайдером, ручная выдача доступа).
2. **Продакшен**: Mercado Pago (ARS), Stripe (USD; доступность для аргентинского юрлица
   уточнить) и крипто-шлюз (стейблкоины).

Слой `billing` провайдер-независимый. Цены хранить в БД и пересматривать: при инфляции
фиксированная цена в песо быстро обесценивается.

## Идея на будущее: ИИ-помощник по документам

Для дел о гражданстве: подтягивать документы из дела (определения, oficios, dictamen…),
извлекать текст и **кратко объяснять человеческим языком**: что это за документ, зачем он нужен,
что требуется от человека и в какой срок. Результат показывать прямо в интерфейсе.

## Что уже умеет прототип (`Parser_juzgado`) — переиспользуем

- Обход номеров дел CNE, отбор дел о гражданстве; проверка пропусков и ошибок.
- Разбор хода дела на этапы с учётом **двух процедур** (старой и новой), расчёт сроков
  (медиана / максимум по парам этапов), «вне канона», индикаторы.
- RENAPER (браузер + токен reCAPTCHA), Correo Argentino (HTTP), история событий.
- Telegram-бот с подписками, интервалом и «проверить сейчас».
- Журнал событий и обнаружение изменений.

## Принципы

- **Только свои данные**: пользователь отслеживает собственные трамите; в условиях явно указать.
- **Минимум персональных данных**, шифрование чувствительных полей, возможность удалить аккаунт.
- **Бережно к источникам**: общий кэш и дедупликация запросов (один и тот же публичный номер дела
  проверяем один раз для всех), лимиты частоты, никакого обхода защит. Если сайт недоступен или
  закрылся — честно показываем «источник недоступен», а не молчим.
- **Прозрачность**: сервис неофициальный и не связан с госорганами; данные могут запаздывать.

## Риски и открытые вопросы

- **Юридическое**: персональные данные (в т.ч. дата рождения, номера трамите) — закон 25.326,
  возможная регистрация базы данных в AAIP; условия использования госсайтов; ответственность за
  уведомления. Нужна консультация юриста до запуска платной версии.
- **Техническое**: у госсайтов нет API; защита от ботов (WAF, reCAPTCHA) и нестабильность;
  ходить из дата-центра может блокироваться иначе, чем с домашнего IP. Нужны адаптеры
  с мониторингом «сломался парсер».
- **Продуктовое**: название, домен, языки, тарифы, что входит в бесплатный план, как проверять
  принадлежность трамите пользователю.

## Черновик технологического стека (TypeScript везде)

Монорепозиторий `pnpm` + Turborepo: `apps/web`, `apps/worker`, `packages/db`, `packages/checkers`,
`packages/shared`.

| Слой | Выбор |
|------|-------|
| Веб + API | Next.js (App Router) + React + TypeScript, Tailwind (+ shadcn/ui), валидация zod |
| БД | PostgreSQL + **Prisma** (ORM и миграции) |
| Фоновые задачи | отдельный Node-воркер; очередь pg-boss (Postgres) или BullMQ (Redis) |
| Парсеры | адаптеры `Checker` в `packages/checkers`: Playwright для сайтов с JS/reCAPTCHA, fetch для простых |
| Auth | Auth.js / Better Auth; вход по e-mail и/или Telegram |
| Telegram | grammY, привязка по одноразовому коду / deep link |
| Платежи | Mercado Pago (ARS), крипто-шлюз; провайдер-независимый слой `billing` |
| i18n | next-intl (RU, ES) |
| ИИ (позже) | Claude API: PDF → текст → пояснение, кэш по документу |
| Инфраструктура | Docker Compose (web, worker, postgres, caddy), VPS, CI, Sentry |

Исключение: капча PJN решается OCR-библиотекой `ddddocr` (Python). На старте — небольшой
Python-«сайдкар» только для PJN; позже можно портировать модель на `onnxruntime-node`.

## Этапы

0. Скелет: репозиторий, Docker, CI, миграции, базовая вёрстка.
1. Аккаунты, профиль, привязка Telegram, выбор событий.
2. Трекеры: RENAPER + Correo (код уже есть) → PJN → Migraciones (по мере доступности сайтов).
3. Расписание, дедупликация, мониторинг адаптеров.
4. Полезные ссылки и блог.

## Запуск локально

Один раз:

```bash
pnpm install                    # зависимости + генерация Prisma-клиента
cp .env.example .env            # затем впишите TELEGRAM_BOT_TOKEN и TELEGRAM_BOT_USERNAME
pnpm db:create-test             # (нужно только для тестов) тестовая БД ojo_test
```

Каждый день:

```bash
pnpm dev        # БД в Docker + миграции + сайт/API (http://localhost:3000) + Telegram-бот
                # Ctrl+C останавливает сайт и бота; контейнер БД остаётся
pnpm db:down    # остановить контейнер БД
```

Отдельно: `pnpm dev:web`, `pnpm dev:worker`, `pnpm test`, `pnpm lint`, `pnpm typecheck`, `pnpm build`.
Сайт и API — одно приложение Next.js (`apps/web`, API в `src/app/api`); бот — `apps/worker`.

## Сборщик данных (Python-сайдкар)

RENAPER, Correo Argentino и PJN читает пакет `services/scraper` (Python + Playwright;
капча PJN решается через `ddddocr`). Worker и web вызывают его как `python -m scraper …`
и получают JSON. Опрос всех активных дел — раз в 3 часа (константа
`TRACKER_CONFIG.checkIntervalHours`, пользователю не видна).

Один раз на машине (внутри проекта, ничего не ставится в систему):

```bash
cd services/scraper
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium
```

Пути настраиваются переменными `SCRAPER_*` (см. `.env.example`). При деплое образ
worker должен содержать Python 3, это venv и браузер (`playwright install --with-deps chromium`).

## Идеи на потом

- **Главная как дашборд** (вернуться, когда все 5 сервисов работают): общая аналитика по
  подпискам и свободным слотам по разделам, сроки (подписка скоро закончится, пробный период
  заканчивается), приостановленные дела, последние события.

## Выключенные функции

**Близкие и слоты** (несколько людей на одном аккаунте, оплата слотов) реализованы, но
выключены: `FEATURE_RELATIVES` (по умолчанию `false`). Пока выключено: один пользователь,
одно отслеживание в разделе, месячная подписка, пробный период на одно дело. Включать
только после решения, как контролировать замену людей (см. обсуждение: слот закрепляется
до конца оплаченного периода, замена возможна при продлении).

## Как добавить новость

Новости — Markdown-файлы в `apps/web/content/news/`. Имя: `YYYY-MM-DD-slug.<язык>.md`
(`ru` и/или `es`; если перевода нет, показывается русская версия). В начале файла:

```
---
title: Заголовок
summary: Короткое описание для списка
---

Текст в Markdown.
```

Добавили файл, закоммитили, запушили — новость появилась в разделе «Новости проекта»
и в блоке «Последние новости» на главной.
