# Ojo de Halcón

Сервис, в котором человек следит за своими государственными делами в Аргентине (DNI, посылки Correo
Argentino, гражданство) **в одном месте** и получает уведомление в Telegram, как только что-то
меняется. Не нужно ходить по очереди на разные сайты.

Репозиторий: `goha1907/Ojo-de-Halcon`. Сервис неофициальный и не связан с государственными органами.

**Кабинет**: дашборд (сводка, что требует внимания), разделы по сервисам с карточками дел, фильтры,
сортировка и поиск, настройки (профиль, уведомления, подписка), обратная связь, полезные ссылки.

**Уведомления**: Telegram-бот (привязка одноразовым кодом); включаются по сервисам и по делам.

**Лендинг** (RU/ES): как это работает, цены с калькулятором, FAQ, новости, юридические ссылки.

**Подписка и оплата**: см. ниже. Платёжный путь полностью работает на тестовом провайдере.

## Как устроена подписка

Подписка считается **по отслеживаниям** (делам), а не по людям или разделам. Цены по лесенке
(`packages/shared/src/config/pricing.ts`): 1 дело, 2 дела, 3, 4 и дальше `+extraCase` за каждое
следующее. Пробный период: одно бесплатное место на 7 дней с создания аккаунта.

- **Пробный период** отдельная вещь: одно место на 7 дней, включается при регистрации. Он заканчивается по
  сроку, при оформлении подписки или когда человеку начисляют подарочные места.
- **Подарочные места** (подарок, партнёрский доступ) работают как платные, но денег не стоят и стоят в очереди
  первыми. Начисляются из админки: количество и дата окончания (без даты они продлеваются каждый месяц, пока их
  не отзовут). Не продаются. Когда срок кончается, отслеживания без места останавливаются, а владельцу приходит
  сообщение. В кабинете о подарочных местах говорят только тем, у кого они есть. Начисляет ядро
  (`core.grants.give`), в админке будет форма.
- Докупка дел действует сразу, дата продления не меняется.
- Отслеживание можно «убрать из подписки»: оно работает до конца оплаченного периода,
  остаётся в истории, сумма следующего периода уменьшается.
- Когда дело завершилось (конечный статус источника), место освобождается автоматически.
- Отмена подписки отключает только автопродление: всё работает до конца периода,
  отметки на делах лишь считает калькулятор.
- Чужие дела (родственник, друг) ведутся в том же аккаунте, у каждого своё название и,
  для Migraciones, своя дата рождения владельца.

Оплата: окно покупки с выбором способа (карта, QR), провайдер подключается через адаптер.
Заглушка включается переменной `PAYMENTS_STUB` (вне production включена). Подробно: [docs/PAYMENTS.md](docs/PAYMENTS.md).

## Структура репозитория

```
apps/web          Next.js: интерфейс и API (src/app/api), новости в content/news
apps/worker       фоновые задачи: опрос источников, Telegram-бот, рассылка
packages/core     бизнес-логика: подписка, отслеживания, платежи, доступ, аккаунты
packages/db       Prisma-схема, миграции, клиент
packages/shared   конфиг (цены, статусы, лимиты), i18n-словари, схемы валидации, типы
packages/ui       общие UI-компоненты
services/scraper  Python-сборщик данных (RENAPER, Correo, Migraciones, PJN)
scripts/          dev-запуск, тестовая БД, статистика статусов
docs/             документы проекта
```

Правило: страницы и обработчики только собирают, логика лежит в `packages/core`, текст интерфейса в
`packages/shared/src/i18n` (источник правды `ru.ts`, у `es.ts` те же ключи).

## Запуск локально

Один раз:

```bash
pnpm install                    # зависимости + генерация Prisma-клиента
cp .env.example .env            # впишите TELEGRAM_BOT_TOKEN, TELEGRAM_BOT_USERNAME, SESSION_SECRET
pnpm db:create-test             # тестовая БД ojo_test (нужна для тестов)
```

Каждый день:

```bash
pnpm dev        # БД в Docker + миграции + сайт/API (http://localhost:3000) + Telegram-бот
                # Ctrl+C останавливает сайт и бота; контейнер БД остаётся
pnpm db:down    # остановить контейнер БД
```

Отдельно: `pnpm dev:web`, `pnpm dev:worker`, `pnpm test`, `pnpm lint`, `pnpm typecheck`, `pnpm build`,
`pnpm db:studio`. Перед завершением задачи прогоняем `typecheck`, `lint` и `test`.

## Сборщик данных (Python)

Worker и web вызывают `python -m scraper …` и получают JSON. Опрос всех активных дел раз в 3 часа
(`TRACKER_CONFIG.checkIntervalHours`).

Один раз на машине (внутри проекта, ничего не ставится в систему):

```bash
cd services/scraper
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium
```

Пути настраиваются переменными `SCRAPER_*` (см. `.env.example`). Образ worker на production должен
содержать Python 3, это venv и браузер (`playwright install --with-deps chromium`).
Тесты: `cd services/scraper && .venv/bin/python -m unittest discover -s tests`.

### Доступ к Migraciones из «закрытой» сети

Сайт Migraciones не отвечает на часть адресов (в том числе у некоторых домашних провайдеров).
Для разработки используется бесплатный Cloudflare WARP в контейнере, и только для этого источника:

```bash
docker compose --profile proxy up -d warp      # SOCKS5 на 127.0.0.1:1080
# .env:
MIGRACIONES_PROXY=socks5h://127.0.0.1:1080
```

В сборщике источник подключается через `scraper.net`. Источники без переменной `<ИСТОЧНИК>_PROXY`
ходят напрямую. На production-хосте переменную не задают, если сайт доступен.

## Статусы и статистика

Каждый новый статус дела и название нового этапа записываются в таблицу `StatusObservation`
(без пользователя, номера и дат: только вид источника, поле, значение, сколько раз встретилось).
Так мы узнаём, какие статусы существуют и какие из них конечные.

```bash
scripts/status-stats.sh            # все источники
scripts/status-stats.sh DNM_DNI    # только DNI в Migraciones
```

Конечные статусы (завершают дело: место освобождается, отслеживание уходит в историю) заданы
в одном месте, `packages/shared/src/config/final-statuses.ts`:

| Раздел | Конечный статус |
|---|---|
| DNI — Migraciones | `RESUELTO` |
| DNI — RENAPER | `Embalado` (передача на почту дело не закрывает: почтовые этапы показываются в этой же карточке) |
| CORREO ARGENTINO | `Entregado` (возврат отправителю пока не определён) |
| CIUDADANÍA — Migraciones | пока неизвестен, копим статистику |
| CIUDADANÍA — суд | `Archívese` |

Сравнение без учёта регистра и акцентов. Новый конечный статус добавляется одной строкой в этот файл.

## Новости

Markdown-файлы в `apps/web/content/news/`. Имя: `YYYY-MM-DD-slug.<язык>.md` (`ru` и/или `es`;
если перевода нет, показывается русская версия). В начале файла:

```
---
time: 15:30
title: Заголовок
summary: Короткое описание для списка
---

Текст в Markdown.
```

Порядок: по дате из имени файла и времени `time` (`ЧЧ:ММ`, без него полночь), от новых к старым.
Добавили файл, закоммитили, запушили: новость появилась на главной в блоке «Новости».
Новость пишем вместе с каждой заметной для пользователя функцией.

## Принципы

- **Только свои данные**: пользователь отслеживает собственные дела; это сказано в условиях.
- **Минимум персональных данных**, удаление аккаунта с подтверждением паролем. Имя держателя,
  которое показывает Migraciones, выводится один раз для подтверждения и не сохраняется.
- **Бережно к источникам**: дедупликация запросов, лимиты частоты, никакого обхода защит. Если сайт
  недоступен, показываем «источник недоступен», а не молчим.
- **Прозрачность**: данные могут запаздывать, сервис сообщает статус источника и не заменяет юриста.

## Риски и открытые вопросы

- **Юридическое**: персональные данные (закон 25.326, возможная регистрация базы в AAIP), условия
  использования госсайтов, ответственность за уведомления. Нужна консультация юриста до платного запуска.
- **Техническое**: у госсайтов нет API, возможны WAF, reCAPTCHA и блокировки по IP; парсеры ломаются при
  смене разметки, нужен мониторинг здоровья источников.
- **Продуктовое**: платёжная система для рекуррентных платежей в Аргентине, хостинг, домен.

Открытые вопросы и план их закрытия: [docs/PLAN.md](docs/PLAN.md).
