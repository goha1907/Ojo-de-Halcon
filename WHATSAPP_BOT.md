# Бот в WhatsApp: как развернуть (инструкция для новичка)

Эта инструкция написана для человека, который никогда не работал с ботами в WhatsApp.
Идём по шагам: сначала разбираемся, что вообще нужно, затем кликаем в кабинете Meta, затем
заполняем `.env`. Код бота в проекте ещё не написан: он появится, когда у вас будут данные из
раздела «6. Что записать в `.env`».

> Цены, лимиты и названия кнопок у Meta меняются. Если что-то в интерфейсе выглядит не так,
> как здесь, ищите по смыслу. Актуальную документацию всегда можно открыть здесь:
> <https://developers.facebook.com/docs/whatsapp/cloud-api>

---

## 0. Что мы строим

Бот делает две вещи:

1. **Привязка аккаунта.** Пользователь в кабинете нажимает «Привязать WhatsApp», получает
   одноразовый код и отправляет его нашему номеру в WhatsApp (так же, как сейчас с Telegram).
   Бот получает сообщение и связывает номер телефона с аккаунтом.
2. **Уведомления.** Когда статус отслеживания изменился, бот отправляет сообщение в WhatsApp.

Важное правило WhatsApp, из-за которого всё устроено именно так:

- Пока человек **сам написал вам** (например, отправил код), у вас есть **24 часа**, чтобы отвечать
  ему любыми текстами. Это окно называется *service window*.
- Когда окно закрыто, писать первым можно **только по заранее одобренному шаблону**
  (*message template*). Уведомление «статус изменился» это как раз такой шаблон.

То есть вам нужно: (а) официальный доступ к WhatsApp, (б) номер телефона, (в) пара шаблонов,
(г) публичный адрес, на который WhatsApp будет присылать входящие сообщения.

## 1. Словарь (чтобы не теряться)

| Термин | Что это простыми словами |
|---|---|
| **Meta Business (Business Portfolio)** | «Компания» в Meta. К ней привязаны ваши приложения, номера и платёжные данные |
| **App (приложение)** | Заготовка на developers.facebook.com, через которую вы получаете доступ к API |
| **WhatsApp Business Account, WABA** | Контейнер для ваших номеров и шаблонов сообщений |
| **Phone Number ID** | Внутренний идентификатор номера в API (это не сам номер телефона) |
| **Access Token** | Секретный ключ, которым вы подписываете запросы. Как пароль |
| **Cloud API** | Официальный способ отправлять сообщения от Meta (серверы Meta, вам не нужен свой сервер WhatsApp) |
| **Template (шаблон)** | Заранее согласованный Meta текст с переменными, например `{{1}}` |
| **Webhook** | Адрес на вашем сервере, куда WhatsApp присылает входящие сообщения |
| **Verify Token** | Любая строка, которую вы придумываете сами, чтобы Meta проверила ваш webhook |
| **App Secret** | Секрет приложения, нужен, чтобы проверять, что webhook действительно от Meta |

## 2. Что понадобится заранее

1. **Личный аккаунт Facebook** (под ним вы войдёте на developers.facebook.com).
2. **Номер телефона для бота**, который:
   - принимает SMS или звонок (для подтверждения);
   - **не используется в обычном приложении WhatsApp**: номер, привязанный к API, нельзя
     одновременно держать в приложении (если на нём уже есть WhatsApp, придётся удалить аккаунт
     в приложении или взять другой номер). Для первых тестов номер **не нужен**: Meta даёт
     бесплатный тестовый (см. шаг 3).
3. **Публичный HTTPS-адрес** для webhook. На время разработки подойдёт бесплатный туннель
   Cloudflare (шаг 5), дальше нужен ваш домен и хостинг.
4. **Для боевого запуска:** ссылка на политику конфиденциальности (она есть в футере лендинга,
   только пока с текстом-заглушкой) и, если хотите писать больше первых 250 людей в сутки,
   верификация бизнеса в Meta (нужны документы компании или ИП/monotributo).

## 3. Создаём приложение и пробуем отправить первое сообщение

Всё это бесплатно и не требует вашего номера.

1. Откройте <https://developers.facebook.com/> и войдите через Facebook.
2. Если просят, пройдите регистрацию разработчика (подтверждение телефоном).
3. **My Apps → Create App** (Мои приложения → Создать).
4. На вопрос «What do you want your app to do?» выберите вариант с бизнес-сообщениями
   (**Other** → тип приложения **Business**). Название любое, например `Ojo de Halcon`.
5. Если спросят про Business Portfolio, создайте новый или выберите существующий.
6. На панели приложения найдите продукт **WhatsApp** и нажмите **Set up**.
7. Откроется **WhatsApp → API Setup**. Здесь вы увидите:
   - **Temporary access token** (временный токен, живёт 24 часа);
   - **Phone number ID** тестового номера (Meta выдаёт тестовый «From» номер);
   - **WhatsApp Business Account ID**.
   Перепишите их, они понадобятся ниже.
8. В блоке **To** добавьте **свой личный номер** как получателя (до 5 штук) и подтвердите
   кодом, который придёт в WhatsApp.
9. Нажмите **Send message** (шаблон `hello_world`). На ваш личный WhatsApp придёт сообщение
   от тестового номера. Если пришло, вы уже управляете API.

Проверка из терминала (подставьте свои значения):

```bash
curl -X POST "https://graph.facebook.com/v21.0/<PHONE_NUMBER_ID>/messages" \
  -H "Authorization: Bearer <ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "messaging_product": "whatsapp",
    "to": "549XXXXXXXXXX",
    "type": "template",
    "template": { "name": "hello_world", "language": { "code": "en_US" } }
  }'
```

Номер получателя пишется **цифрами с кодом страны, без `+` и пробелов**. Для мобильных
Аргентины это формат `549` + код города + номер.

## 4. Постоянный токен (чтобы бот не «ломался» каждый день)

Временный токен из шага 3 живёт сутки. Для постоянной работы нужен токен системного
пользователя:

1. Откройте <https://business.facebook.com/settings> (**Business Settings**).
2. **Users → System users → Add**. Роль: **Admin**.
3. Нажмите **Add assets**: добавьте своё **приложение** (с полным управлением) и свой
   **WhatsApp account** (WABA).
4. Нажмите **Generate new token**, выберите приложение и отметьте права:
   `whatsapp_business_messaging` и `whatsapp_business_management`. Срок: **Never** (без
   истечения).
5. Скопируйте токен **сразу** (повторно его показать нельзя) и храните как пароль: в `.env`
   и больше нигде. **Никогда не коммитьте его в git.**

## 5. Webhook: как бот узнаёт, что ему написали

WhatsApp сам пришлёт на ваш адрес запрос, когда человек отправит сообщение. Для этого нужен
адрес, доступный из интернета.

### 5.1 Временный адрес для разработки (бесплатно)

Установите `cloudflared` (<https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/>)
и запустите, пока работает сайт на порту 3000:

```bash
cloudflared tunnel --url http://localhost:3000
```

В выводе будет адрес вида `https://что-то-случайное.trycloudflare.com`. Он меняется при
каждом запуске. Для постоянного адреса понадобится свой домен.

### 5.2 Подключаем webhook

1. Придумайте **Verify Token**: любая длинная случайная строка. Запишите её.
2. **WhatsApp → Configuration → Webhook → Edit**.
3. **Callback URL**: `https://<ваш-адрес>/api/whatsapp/webhook` (этот маршрут надо будет
   создать в коде, см. раздел 7).
4. **Verify token**: ваша строка. Нажмите **Verify and save**. Проверка пройдёт, только когда
   наш сервер уже отвечает на этот адрес.
5. В списке **Webhook fields** подпишитесь на поле **`messages`**.
6. **App Secret** найдите в **App settings → Basic → App secret → Show**. Он нужен, чтобы
   проверять подпись `X-Hub-Signature-256` на каждом входящем запросе и отбрасывать подделки.

## 6. Что записать в `.env`

Все значения хранятся только в файле `.env`. В репозиторий они не попадают.

| Переменная | Откуда взять | Секрет? |
|---|---|---|
| `WHATSAPP_ACCESS_TOKEN` | Токен системного пользователя (шаг 4) | да |
| `WHATSAPP_PHONE_NUMBER_ID` | WhatsApp → API Setup → Phone number ID | нет |
| `WHATSAPP_BUSINESS_ACCOUNT_ID` | WhatsApp → API Setup → WhatsApp Business Account ID | нет |
| `WHATSAPP_VERIFY_TOKEN` | Строка, которую вы придумали (шаг 5.2) | да |
| `WHATSAPP_APP_SECRET` | App settings → Basic → App secret | да |
| `WHATSAPP_API_VERSION` | Версия Graph API, например `v21.0` (смотрите актуальную в документации) | нет |
| `WHATSAPP_TEMPLATE_STATUS_CHANGED` | Имя вашего шаблона уведомления (шаг 8) | нет |

Пример:

```env
WHATSAPP_ACCESS_TOKEN=EAAG...очень_длинная_строка
WHATSAPP_PHONE_NUMBER_ID=123456789012345
WHATSAPP_BUSINESS_ACCOUNT_ID=987654321098765
WHATSAPP_VERIFY_TOKEN=придуманная_случайная_строка
WHATSAPP_APP_SECRET=abcdef0123456789abcdef0123456789
WHATSAPP_API_VERSION=v21.0
WHATSAPP_TEMPLATE_STATUS_CHANGED=tracking_status_changed
```

## 7. Что нужно сделать в коде проекта (когда данные у вас есть)

Это работа для разработки, ничего кликать не нужно. Список, чтобы вы понимали объём:

1. Маршрут `GET /api/whatsapp/webhook`: отвечает на проверку Meta (возвращает `hub.challenge`,
   если `hub.verify_token` совпал).
2. Маршрут `POST /api/whatsapp/webhook`: проверяет подпись `X-Hub-Signature-256` по
   `WHATSAPP_APP_SECRET`, разбирает входящее сообщение и, если в нём код привязки, связывает
   номер с аккаунтом.
3. Отправитель в `packages/core`: `sendText` (внутри 24-часового окна) и `sendTemplate`
   (уведомления).
4. В карточке «WhatsApp» (Настройки → Профиль): кнопка «Привязать», показ кода и статуса.
5. Колонка `notifyWhatsapp` у отслеживаний уже есть в базе, в сетке уведомлений чекбокс сейчас
   выключен: включим его, когда отправитель будет готов.
6. Правила «стоп»: если человек пишет `STOP` или `БАЙ`, бот отключает ему WhatsApp-уведомления.

## 8. Шаблоны сообщений (обязательно для уведомлений)

Без одобренного шаблона вы не сможете отправлять уведомления тем, кто давно не писал боту.

1. Откройте <https://business.facebook.com/wa/manage/message-templates/> (**WhatsApp Manager →
   Message templates**).
2. **Create template**.
3. **Category: Utility** (служебные: статус, уведомление о событии). Не выбирайте *Marketing*:
   оно дороже и строже проверяется.
4. **Name:** `tracking_status_changed` (строчные латинские буквы и подчёркивания).
5. **Language:** Russian (и отдельно Spanish, если нужен испанский вариант).
6. **Body**, пример:

   ```
   Ojo de Halcón: по отслеживанию № {{1}} изменился статус. Сейчас: {{2}}.
   Подробности в личном кабинете.
   ```

7. Добавьте примеры для переменных (`123456789` и `Verificado`) и отправьте на проверку.
8. Одобрение обычно занимает от нескольких минут до часов. Статус должен стать **Active**.

Советы по одобрению:

- Не используйте в шаблоне ссылки-сокращатели и слова вроде «акция» (это маркетинг).
- Переменные не должны стоять первыми или последними в тексте.
- Текст должен быть полезен получателю и ожидаем им, он сам подписался на уведомления.

## 9. Боевой номер вместо тестового

Когда всё работает на тестовом:

1. **WhatsApp → API Setup → Add phone number** (или в WhatsApp Manager → Phone numbers).
2. Введите номер, имя компании, подтвердите кодом по SMS/звонку.
3. **Display name** проходит проверку Meta: оно должно совпадать с названием бизнеса.
4. Задайте двухэтапный PIN (6 цифр) и сохраните его.
5. Замените `WHATSAPP_PHONE_NUMBER_ID` в `.env` на ID нового номера.
6. Переведите приложение в **Live mode** (переключатель вверху панели приложения). Для этого
   Meta попросит ссылку на политику конфиденциальности и иконку приложения. Пока приложение
   в режиме Development, ему могут писать только добавленные тестеры.

## 10. Сколько это стоит и какие есть ограничения

- **Ответы внутри 24-часового окна** (человек написал сам) бесплатны.
- **Шаблоны (уведомления)** платные, **за каждое сообщение**, цена зависит от категории
  (Utility дешевле Marketing) и страны получателя. Актуальные тарифы для Аргентины смотрите на
  <https://developers.facebook.com/docs/whatsapp/pricing>. Платёжный способ добавляется в
  Business Settings. С апреля 2026 года Meta принимает оплату в песо (ARS).
- **Лимиты отправки:** новый номер начинает с лимита около 250 людей в сутки, который растёт
  по мере качества и верификации бизнеса.
- **Качество:** если люди массово жалуются или блокируют номер, Meta снижает лимиты и может
  отключить номер. Поэтому пишем только тем, кто сам привязал WhatsApp.

## 11. Правила и безопасность

1. **Согласие.** Пишем только тем, кто привязал WhatsApp сам (отправил код). Это и есть opt-in.
2. **Отписка.** Всегда даём способ выйти: слово `STOP`, галочка в сетке уведомлений.
3. **Не используйте неофициальные библиотеки** (whatsapp-web.js, Baileys и аналоги) для
   рабочего бота: они работают через «взломанное» подключение, нарушают правила WhatsApp, а
   номер банят без предупреждения.
4. **Токены и App Secret только в `.env`.** Если токен утёк, выпустите новый и удалите старый.
5. **Персональные данные.** Номера телефонов и содержимое сообщений не пишем в логи.

## 12. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `Verify and save` в webhook не проходит | Сервер доступен снаружи по HTTPS? Verify token в `.env` и в Meta одинаковые? Маршрут отвечает `hub.challenge`? |
| `(#131030) Recipient phone number not in allowed list` | Приложение в Development: добавьте номер получателя в список тестовых (шаг 3.8) |
| `(#132000)/(#132001) template ... does not exist` | Имя или язык шаблона не совпадает, либо он ещё не Active |
| `(#131047) Re-engagement message` | Окно 24 часа закрыто: нужно отправлять шаблон, а не обычный текст |
| `190 Invalid OAuth access token` | Токен истёк (был временный) или скопирован не полностью |
| Входящие не приходят | Не подписаны на поле `messages`, или туннель сменил адрес |
| Сообщение «принято», но не доставлено | Получатель заблокировал номер, не писал вам, или у него старая версия WhatsApp |
